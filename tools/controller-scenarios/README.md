# Проверка слоёв и событий ванильного геймпада

## Подготовка игры

1. Запусти игру с новой сборкой GamepadTweaks и одобри JAR в ZombieBuddy, если загрузчик запросит подтверждение.
2. Для этой проверки используй обычный ввод геймпада. В профиле Steam Input оставь передачу обычных кнопок и осей, если он включён.
3. В «Настройки → Контроллер» выбери **Default**, затем «Добавить». Игра присвоит имя, например **Пользовательский_1** или **Custom**. Нажми «Применить» и оставь этот пресет активным. Закрой настройки. Для сценариев подойдёт тестовый мир с машиной на ровной дороге, выключателем или дверью и предметом в открытом окне добычи.
4. Из корня репозитория задай путь к файлу игры. Для рабочего окружения подходит путь ниже. Игру можно оставить запущенной.

```sh
gt_settings=/mnt/data/Games/Zomboid/GamepadTweaks.properties
gt_preset='Пользовательский_1'
python3 tools/controller-scenario.py layers "$gt_settings" --preset "$gt_preset"
```

Подставь в `gt_preset` имя из игры. Скрипт заменяет ключи сценариев только для этого пресета. `GamepadTweaks.properties` перечитывается примерно раз в секунду. Дождись новой строки `button actions (имя пресета)` в `console.txt`. Файл XML в `InputBindings` используется как база и остаётся тем же. GamepadTweaks должен быть включён в самом сохранении. Если последняя загрузка в `console.txt` прошла с `0 mods`, скрипт предупредит: игра прочитает сценарий после загрузки сохранения с модом.

## Слои и подсказки

| Сцена | Действие | Что должно произойти |
| --- | --- | --- |
| Пешком рядом с выключателем | Нажать RB, затем LB | RB переключает приседание, LB включает или выключает свет. Подсказка взаимодействия, если она видна, стоит на LB. |
| Пешком у двери | Коротко нажать LB, затем A отдельно | Дверь открывается или закрывается через LB. A больше не вызывает это действие в слое «Пешком». Так проверяется Java-опрос, а не только Lua-подсказка. |
| Пешком рядом с водительской дверью | Сесть через LB | У водительского места появляется подсказка входа на LB. В салоне подсказка выхода переставляется на RB. |
| За рулём на небольшой скорости | Зажать LB и отпустить, затем отдельно нажать RB на остановленной машине | Пока зажат LB, работает тормоз. RB выводит из машины. После выхода RB снова переключает приседание. |
| Открыто окно добычи с выбранным предметом | Нажать X, затем RB | X больше не переносит предмет в этом окне. RB переносит его. За пределами окна RB работает по текущему слою мира. |
| За рулём, экран без панели | Удерживать X и нажать крестовину вверх или вниз | Штатная скорость круиза меняется. В редакторе нет вкладки «Круиз». Скорость можно назначить отдельно через «С модификатором» в «Транспорте». |

В редакторе также проверь, что «Присесть» предлагается в «Пешком», «Тормоз» — в «Транспорте», а в «Общих» видны старые назначения. После удаления назначения из слоя убедись, что возвращается назначение из «Общих». Повторный запуск сценария восстанавливает тестовые строки.

## События

```sh
python3 tools/controller-scenario.py events "$gt_settings" --preset "$gt_preset"
```

| Сцена | Действие | Что должно произойти |
| --- | --- | --- |
| Пешком, инвентарь закрыт | Один короткий B | Персонаж приседает или встаёт после окна двойного нажатия в 190 мс. |
| Там же | Два быстрых нажатия B с отпусканием между ними | Открывается инвентарь. Положение персонажа сохраняется. Для повторения закрой инвентарь штатной кнопкой. |
| Пешком у выключателя | Зажать B примерно на полсекунды | Через 300 мс свет меняется один раз. Инвентарь не открывается, приседание не переключается. |
| Пешком с безопасным направлением для атаки | Отклонить правый стик без RB. Затем зажать RB, не отпуская стик, и медленно нажать RT | Стик поворачивает персонажа без RB. RB панорамирует камеру, а RT управляет штатным точным прицелом. Атака начинается около 90% хода RT. Верни стик в центр, затем снова отклони его. Прицеливание возобновляется. |
| За рулём на небольшой скорости | По отдельности нажать LB и RB. Затем зажать LB, нажать RB и отпустить RB. Повторить в обратном порядке | Отдельные бамперы не тормозят. В обоих порядках тормоз работает, пока зажата основная кнопка комбинации. |

После теста верни обычный пресет. При необходимости очисти тестовые назначения.

```sh
python3 tools/controller-scenario.py clear "$gt_settings" --preset "$gt_preset"
```

## Отдельная проверка замены прицеливания

```sh
python3 tools/controller-scenario.py aim-override "$gt_settings" --preset "$gt_preset"
```

Только в этом сценарии «Пешком → Прицеливание» намеренно переносится с правого стика на RB. Стик задаёт направление при зажатом RB. При возврате стика в центр и повторном отклонении удержание RB продолжает прицеливание и не открывает меню перезарядки. Пока RB удерживает прицеливание, панорамирование на том же нажатии не включается. Для возврата к штатному стику и панорамированию снова запусти `events`.

## Автотесты вне игры

```sh
lua tools/test_controller_bindings.lua

./build.sh
pz_dir=/mnt/data/SteamLibrary/steamapps/common/ProjectZomboid/projectzomboid
/usr/lib/jvm/java-25-openjdk/bin/java --class-path "build/classes:$pz_dir/*" tools/NativeBindingInputTest.java
```

Lua-тест использует те же сценарии и подставляет время, кнопки и контекст. Он проверяет выбор слоя, вызов Lua-обработчика, пороги, граничное время двойного нажатия, удержание, смену контекста, две очередности комбинации и состояние двух игроков. Java-тест использует штатный `TimedInputHandler` из JAR игры и проверяет состояния нажатия, отпускания и клика. Сценарии в игре проверяют физический контроллер и реальные действия в мире.
