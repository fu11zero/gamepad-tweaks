# План: слои в ванильном редакторе геймпада

Запрос игрока: слои в «Настройки → Контроллер», как в Steam Input. Сверху — разнести действия по слоям,
а возможно, ещё и показать иконки. Это скорее наша недоделка. Изначально хотели, чтобы в игре
настраивались сила нажатия, долгое нажатие и двойной клик (старый план нигде не записан, восстановлен здесь).

## До реализации (на коммите fb87f08)

- Steam: 5 слоёв (`onfoot`/`vehicle`, `aiming`, `ui`, `inventory`), игрок сам решает, что в каком слое.
  Слои выбирает `Bindings.lua` каждый кадр (`GamepadTweaks_steamInputSetLayers`).
- Ванильный редактор (`ControllerEditor.lua`): на кнопку один список. Внутренние слои действий
  (`world`, `cruise`, `aiming`, `hold`, `uiHold`, `navigation`) зашиты в `layer = ...` каждого действия
  в `Bindings.lua`, игрок их не видит и не выбирает.
- Бинды мода: `preset.<имя>.bind.<действие>` в `GamepadTweaks.properties`.

## Шаги (каждый можно выпускать отдельно)

1. **Слои для действий мода — реализовано.** Вкладки «Общие», «Пешком», «Транспорт», «Прицел»,
   «Панели» и «Инвентарь». Хранение `preset.<имя>.<слой>.bind.<действие>` с миграцией
   старых строк. Назначение и срабатывание биндов проверены игроком в игре.
   Список новых назначений учитывает контекст вкладки. Старые назначения можно заменить или удалить.
   Обновлённые списки проверены игроком в игре.
   Отдельная вкладка «Круиз» удалена. Ускорение и замедление доступны в «Транспорте»
   с обычными модификаторами. Встроенное сочетание для круиз-контроля сохранено.
2. **Иконки — реализовано.** Для ванильных действий и действий мода редактор показывает PNG в строках и выпадающих списках. Вкладки слоёв тоже со значками.
   Значки соответствуют эмодзи из списка действий Steam. Для модификаторов, доступных только
   в игре, добавлены свои значки. Текст виден и при отсутствии текстуры.
   Отображение иконок проверено игроком в игре. В списках остались названия без префиксов категорий.
3. **Модификаторы нажатия — реализованы для действий мода и ванильных действий.** В строке назначения перед действием выбирается событие:
   «Нажатие», «Двойное нажатие», «Удержание» или «С модификатором». У одного ввода в слое может быть
   несколько назначений. Показывать только поля, нужные для выбранного события и типа ввода.
   - Двойное нажатие: по умолчанию 190 мс от первого нажатия до второго, с отпусканием между ними.
     Удержание: по умолчанию 300 мс, срабатывает один раз после достижения порога времени.
     Оба значения редактируются в строке назначения.
   - Существующие действия сохраняют исходный момент срабатывания при отсутствии конфликтующих
     назначений в активном контексте. Для действия на нажатие удержание откладывает короткое действие
     до отпускания, двойное нажатие — до окончания окна. Если назначены оба события, должны пройти
     обе проверки. Распознанное удержание или двойное нажатие отменяет одиночное действие.
   - Модификатор выбирается из других кнопок, триггеров и стиков. Комбинация срабатывает, когда
     модификатор уже зажат, а основной ввод нажат. Для одного действия можно добавить обе комбинации
     с обратным порядком кнопок. Короткое действие самого модификатора выполняется
     при отпускании, если в этом нажатии он не участвовал в комбинации и прошли проверки его
     собственных событий. Собственное удержание модификатора может сработать независимо от комбинации.
   - Для триггеров и стиков настраивается порог срабатывания, в том числе отдельный порог для оси
     в роли модификатора. Для стиков порог задаётся по величине отклонения. Для новых кнопочных
     назначений на осях отпускание распознаётся чуть ниже порога, чтобы небольшое колебание оси
     не считалось повторным нажатием. Ванильные пороги существующих биндов сохраняются
     (Attack на RT — 0.93, Run на левом стике — 0.975).
   - Для ванильных действий непрерывное состояние передаётся в Java. Действия на клик
     получают короткое нажатие и отпускание после распознавания события.
     В `TimedInputHandler` 400 мс — максимум длительности одного ванильного клика.
4. **Ванильные бинды по слоям — реализованы.** Настройки текущего слоя дополняют базовый
   пресет. Например, RB может переключать приседание пешком и выводить из машины за рулём.
   Java читает состояние через `CharacterJoypadButtonBinding` для конкретного контроллера.
   Обработчики подсказок `ISButtonPrompt` выбираются по имени действия. Аналоговое движение
   и направление прицеливания по-прежнему настраиваются ванильным редактором осей.

Слои и события проверены автотестами. [Сценарии проверки в игре](../tools/controller-scenarios/README.md).
